# System files

Root-owned files from `/etc` and `/usr/local/bin` that this laptop depends on.
The install script does not copy them: they control how the machine boots, so
put them in place by hand and check each one first. The folder layout mirrors
the paths on the system.

| File | What it does |
| --- | --- |
| `etc/modprobe.d/thinkpad_acpi.conf` | Lets `bin/set-fan` control the ThinkPad fan |
| `etc/dracut.conf.d/cmdline.conf` | Kernel command line for the unified kernel image: encrypted root unlocked by the TPM, hibernation, fan control, and a quiet boot. The GPU (Meteor Lake) uses `i915`, the driver Intel supports for it; `xe` runs it only when forced, which taints the kernel |
| `etc/dracut.conf.d/tpm2.conf` | Puts the TPM's libraries in the boot image. See [Unlocking with the TPM](#unlocking-with-the-tpm) |
| `etc/dracut.conf.d/drivers.conf`, `flags.conf` | Extra drivers, zstd compression and host-only images |
| `etc/dracut.conf.d/secureboot.conf` | Signs the image with the sbctl keys |
| `etc/pacman.d/hooks/90-dracut-install.hook`, `60-dracut-remove.hook` | Rebuild or remove the kernel image when the kernel package changes |
| `etc/pacman.d/hooks/zz-sbctl.hook` | Re-signs the image after every kernel update |
| `usr/local/bin/dracut-install.sh`, `dracut-remove.sh` | The scripts those hooks run |
| `etc/systemd/system/plymouth-quit.service.d/retain-splash.conf` | Keeps the boot splash on screen until the login screen takes over |
| `etc/systemd/system/systemd-pcrlogin@954.service.d/skip-greeter.conf` | Stops a TPM measurement of the greeter user from holding the login screen back by about 1.7 seconds. `954` is the greeter's user id on this machine; check it with `id -u greeter` and rename the folder if it differs |
| `etc/greetd/config.toml` | The login screen: runs the script below on the first console |
| `usr/local/bin/nocturne-greeter.sh` | Generated by `nocturne/build`. Starts the Nocturne login screen (`greeter/`, copied to `/etc/greetd/nocturne/`) inside labwc, and falls back to tuigreet if that cannot start. Needs `greetd`, `labwc`, `wlr-randr`, `quickshell` and `greetd-tuigreet` |
| `etc/pam.d/polkit-1`, `greetd` | The fingerprint for the polkit password window and the login screen. See [Fingerprint](#fingerprint) |
| `usr/local/bin/lid-closed` | Tells those PAM files that the lid is shut, so they skip the sensor |
| `etc/systemd/sleep.conf.d/hibernate.conf` | Sleep, then hibernate after two hours on battery. See [Sleep](#sleep) |
| `etc/systemd/logind.conf.d/lid.conf` | Closing the lid does the same |

[REINSTALL.md](../REINSTALL.md) installs Arch from the ISO up to these files,
including the swap file that hibernation uses.

## Placeholders in cmdline.conf

`cmdline.conf` holds three values that identify this machine's disks, so the
repo keeps placeholders. Fill them in when installing:

| Placeholder | How to find it |
| --- | --- |
| `<LUKS_UUID>` | `sudo blkid -s UUID -o value /dev/<encrypted partition>` |
| `<SWAP_UUID>` | `findmnt -no UUID -T /swapfile` |
| `<SWAP_OFFSET>` | `sudo filefrag -v /swapfile`, first physical offset; `genswap` prints both swap values |

## Installing

```sh
sudo install -Dm644 etc/modprobe.d/thinkpad_acpi.conf /etc/modprobe.d/thinkpad_acpi.conf
sudo install -Dm644 -t /etc/dracut.conf.d etc/dracut.conf.d/*.conf
sudo install -Dm644 -t /etc/pacman.d/hooks etc/pacman.d/hooks/*.hook
sudo install -Dm755 -t /usr/local/bin usr/local/bin/*.sh
sudo install -Dm644 -t /etc/systemd/system/plymouth-quit.service.d etc/systemd/system/plymouth-quit.service.d/retain-splash.conf
sudo install -Dm644 -t /etc/systemd/system/systemd-pcrlogin@954.service.d etc/systemd/system/systemd-pcrlogin@954.service.d/skip-greeter.conf
sudoedit /etc/dracut.conf.d/cmdline.conf   # replace the three placeholders
```

The fingerprint and sleep files are installed the same way; their sections
below have the commands.

## The boot image

The files in `etc/dracut.conf.d` only take effect when the image is rebuilt.
The pacman hook does that on every kernel update. After changing one by hand,
rebuild the image and check that it is signed:

```sh
sudo dracut --force --uefi --kver "$(uname -r)" /boot/efi/EFI/Linux/bootx64.efi
sudo sbctl verify
```

Keep `compress="zstd"` in `flags.conf`. At boot, systemd-stub adds small
archives after the initramfs, and the kernel's lz4 decoder cannot tell where
the lz4 data ends. With lz4 the kernel logs `Initramfs unpacking failed:
Decoding failed` on every boot. The machine still starts, but the added
archives are lost.

## Unlocking with the TPM

The disk unlocks by itself at boot, as BitLocker does by default: the TPM
holds a key for it and releases that key only when the machine started
through this Secure Boot setup (PCR 7, which records the Secure Boot state
and the keys that checked each step). A USB stick, Secure Boot turned off or
changed keys all make the TPM refuse, and the disk password is asked for
instead; it always stays as the fallback. The login screen is then the one
door, so the password there, and the firmware password, matter more.

Three parameters at the end of `cmdline.conf` go with it:

| Parameter | What it does |
| --- | --- |
| `rd.luks.options=tpm2-device=auto` | Tries the TPM before asking for the password |
| `rd.shell=0` | No shell in the boot image if something fails. The disk is already unlocked by then, so a shell would be a way in |
| `rd.emergency=reboot` | Restarts instead |

The kernel image is signed and carries its own command line, so none of this
can be changed at the boot menu. A firmware (BIOS) password keeps anyone from
turning Secure Boot off, which would only make the TPM refuse, but it closes
that door earlier.

It needs `tpm2-tools` (in `packages/pacman.txt`): without it dracut refuses
its TPM module and stops before writing the image, so the old image boots and
asks for the password. To set it up, add the three parameters to
`/etc/dracut.conf.d/cmdline.conf` (the real one, with the disk identifiers),
then:

```sh
sudo install -Dm644 etc/dracut.conf.d/tpm2.conf /etc/dracut.conf.d/tpm2.conf
sudo dracut --force --uefi --kver "$(uname -r)" /boot/efi/EFI/Linux/bootx64.efi
sudo sbctl verify
```

Restart (it still asks for the password this time), and only then enroll:

```sh
sudo systemd-cryptenroll --tpm2-device=auto --tpm2-pcrs=7 /dev/<encrypted partition>   # asks for the disk password
```

The order matters. Once the boot image has TPM support, systemd marks the
start of the operating system in PCR 7 (`os-separator` in the journal),
before the disk unlocks. Enrolling from a boot without that mark ties the key
to a value no later boot reproduces, and the journal says "TPM policy does
not match current system state".

Restart again: no password prompt means it worked. `journalctl -b | grep -i
cryptsetup` shows the unlock.

**When the TPM refuses.** A firmware update, a Secure Boot key change or a
revocation list update (fwupd installs those) changes PCR 7. The boot then
asks for the disk password once. Type it, then run `tpm-reenroll`
(`bin/tpm-reenroll`). It finds the encrypted disk from the boot command line
and enrolls the TPM again for the current state; `tpm-reenroll status` says
whether the TPM unlocked this boot and lists the disk's key slots.

**If the boot breaks.** With `rd.shell=0` there is no rescue shell. Turn
Secure Boot off in the firmware, start the Arch ISO, unlock the disk with its
password, and fix it from there; with Secure Boot off the TPM will not unlock
anything, which is the point.

**To go back** to typing the password: `sudo systemd-cryptenroll
--wipe-slot=tpm2 /dev/<encrypted partition>`. The three parameters can stay;
without a TPM key they change nothing.

## A quiet boot

The boot should show Plymouth and nothing else: no text before it, and none
between the disk password and the login screen. Two things do that.

Three parameters at the end of `cmdline.conf`:

| Parameter | What it does |
| --- | --- |
| `loglevel=3` | Hides kernel error lines. `quiet` alone still prints them |
| `systemd.show_status=error` | systemd prints failures only, never the `[ OK ]` lines |
| `vt.global_cursor_default=0` | Hides the blinking text cursor |

Two parameters to leave out:

- `plymouth.nolog`. Plymouth tells systemd to print its status lines whatever
  `systemd.show_status` says, and normally catches them itself and writes
  them to `/var/log/boot.log`. With `plymouth.nolog` it does not catch them,
  so they land on the screen for a moment before the splash draws.
- `plymouth.use-simpledrm`. It makes Plymouth draw the password prompt on the
  firmware display about three seconds sooner. But the GPU's driver then
  takes the display over, and the screen goes black until it is ready and
  Plymouth draws again.

And `retain-splash.conf`, which makes Plymouth leave its picture on screen
when it quits. Without it the text console shows for about two seconds, until
greetd clears the screen for the login screen.

The hidden messages are all still in `journalctl -b`. If the login screen
cannot start at all, the first console keeps showing the frozen splash;
`Ctrl + Alt + F2` opens a plain console.

## The login screen

The login screen is separate and does not touch the boot image. One command
installs or updates it:

```sh
nocturne greeter preview   # look at it in a window first
nocturne greeter install   # asks for your password
```

`install` copies the screen to `/etc/greetd/nocturne/`, because the greeter's
user cannot read a home folder, puts the script in `/usr/local/bin`, and
points greetd at it. The desktop's cursor goes along: the theme named in
`hypr/lua/env.lua` is copied into `/etc/greetd/nocturne/icons/` if it lives in
your home folder. The config it replaces is kept as
`/etc/greetd/config.toml.before-nocturne`.

greetd reads its config only when it starts, so the first install shows after
you restart the computer; logging out is not enough. (`sudo systemctl restart
greetd` also works, but it ends your session on the spot.) Later updates show
at the next login.

The copies do not follow the repo by themselves. After changing the accent or
the wallpaper, run `nocturne greeter install` again; `nocturne reload` and
`nocturne doctor` say when they are out of date.

**Sessions.** Every login starts Hyprland unless you pick another session in
the bottom-left corner first (click it, or Tab to it and press Enter). GNOME
appears when it is installed, and i3 when it and `xorg-xinit` are; a session
other than Hyprland shows in gold, and the next boot starts at Hyprland
again. `greeter/session.sh` starts each one: GNOME on Wayland, and i3 through
`startx` on the login's console. GDM can stay installed, disabled, as a way
back to GNOME's own login screen.

If the screen cannot start, the script falls back to tuigreet, the text
login, so you can still get in. It starts Hyprland too; F3 there lists the
other sessions. `Ctrl + Alt + F2` opens a plain console as a
last resort. To go back for good:

```sh
sudo cp /etc/greetd/config.toml.before-nocturne /etc/greetd/config.toml
```

## Fingerprint

Enrol a finger first (`fprintd-enroll`). The lock screen then needs nothing
more: hyprlock talks to the sensor itself, alongside the password. For the
polkit password window and the login screen, the PAM files here put the
fingerprint first:

- **polkit** waits 10 seconds for a finger, then asks for the password.
- **The login screen** starts listening as soon as it shows. A password typed
  in those 10 seconds waits ("Checking") and is sent when the sensor gives up.
  After that only the password works, until a failed try starts over.
- **With the lid closed**, as when docked, both skip the sensor and ask for
  the password straight away (`lid-closed`).

sudo keeps asking for the password straight away. PAM runs one module after
another, so a fingerprint first would hold every sudo back until the sensor
gives up.

A fingerprint cannot unlock the GNOME keyring, which is opened with the login
password. After a fingerprint login, the first app that wants a saved secret
asks for the password once. The disk password at boot stays a password.

```sh
sudo install -Dm755 usr/local/bin/lid-closed /usr/local/bin/lid-closed
sudo cp /etc/pam.d/greetd /etc/pam.d/greetd.before-nocturne
sudo install -Dm644 -t /etc/pam.d etc/pam.d/polkit-1 etc/pam.d/greetd
```

Then try `pkexec true`. The login screen's side shows at the next login. To
go back, copy `greetd.before-nocturne` back and delete `/etc/pam.d/polkit-1`;
polkit then uses `/usr/lib/pam.d/polkit-1` again. When the greetd package
changes its own file, pacman leaves the new one beside it as `.pacnew`.

## Sleep

Sleeping from the power menu, after 30 idle minutes, or by closing the lid
runs `systemctl suspend-then-hibernate`. On battery, the laptop hibernates
after two hours asleep (or sooner, if the battery runs low), so it never
drains flat; on the charger it stays asleep. With an external display
connected, closing the lid still does nothing. Hibernation must already work:
the swap file and the `resume=` values in `cmdline.conf`, as REINSTALL.md
step 6 sets them up.

```sh
sudo install -Dm644 -t /etc/systemd/sleep.conf.d etc/systemd/sleep.conf.d/hibernate.conf
sudo install -Dm644 -t /etc/systemd/logind.conf.d etc/systemd/logind.conf.d/lid.conf
sudo systemctl kill -s HUP systemd-logind   # reads the lid setting again; your session stays
```
