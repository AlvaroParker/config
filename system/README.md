# System files

Root-owned files from `/etc` and `/usr/local/bin` that this laptop depends on.
The install script does not copy them: they control how the machine boots, so
put them in place by hand and check each one first. The folder layout mirrors
the paths on the system.

| File | What it does |
| --- | --- |
| `etc/modprobe.d/thinkpad_acpi.conf` | Lets `bin/set-fan` control the ThinkPad fan |
| `etc/dracut.conf.d/cmdline.conf` | Kernel command line for the unified kernel image: encrypted root, hibernation, fan control, the Intel `xe` driver for this GPU, and a quiet boot |
| `etc/dracut.conf.d/drivers.conf`, `flags.conf` | Extra drivers, zstd compression and host-only images |
| `etc/dracut.conf.d/secureboot.conf` | Signs the image with the sbctl keys |
| `etc/pacman.d/hooks/90-dracut-install.hook`, `60-dracut-remove.hook` | Rebuild or remove the kernel image when the kernel package changes |
| `etc/pacman.d/hooks/zz-sbctl.hook` | Re-signs the image after every kernel update |
| `usr/local/bin/dracut-install.sh`, `dracut-remove.sh` | The scripts those hooks run |
| `etc/systemd/system/plymouth-quit.service.d/retain-splash.conf` | Keeps the boot splash on screen until the login screen takes over |
| `etc/systemd/system/systemd-pcrlogin@954.service.d/skip-greeter.conf` | Stops a TPM measurement of the greeter user from holding the login screen back by about 1.7 seconds. `954` is the greeter's user id on this machine; check it with `id -u greeter` and rename the folder if it differs |
| `etc/greetd/config.toml` | The login screen: runs the script below on the first console |
| `usr/local/bin/nocturne-greeter.sh` | Generated by `nocturne/build`. Starts the Nocturne login screen (`greeter/`, copied to `/etc/greetd/nocturne/`) inside labwc, and falls back to tuigreet if that cannot start. Needs `greetd`, `labwc`, `wlr-randr`, `quickshell` and `greetd-tuigreet` |

See `secure-arch/` for the full setup and `Hibernation.md` for the swap file.

## Placeholders in cmdline.conf

`cmdline.conf` holds three values that identify this machine's disks, so the
repo keeps placeholders. Fill them in when installing:

| Placeholder | How to find it |
| --- | --- |
| `<LUKS_UUID>` | `sudo blkid -s UUID -o value /dev/<encrypted partition>` |
| `<SWAP_UUID>` | `findmnt -no UUID -T /swapfile` |
| `<SWAP_OFFSET>` | `sudo filefrag -v /swapfile`, first physical offset; `genswap` prints both swap values |

## Installing

```sh
sudo install -Dm644 etc/modprobe.d/thinkpad_acpi.conf /etc/modprobe.d/thinkpad_acpi.conf
sudo install -Dm644 -t /etc/dracut.conf.d etc/dracut.conf.d/*.conf
sudo install -Dm644 -t /etc/pacman.d/hooks etc/pacman.d/hooks/*.hook
sudo install -Dm755 -t /usr/local/bin usr/local/bin/*.sh
sudo install -Dm644 -t /etc/systemd/system/plymouth-quit.service.d etc/systemd/system/plymouth-quit.service.d/retain-splash.conf
sudo install -Dm644 -t /etc/systemd/system/systemd-pcrlogin@954.service.d etc/systemd/system/systemd-pcrlogin@954.service.d/skip-greeter.conf
sudoedit /etc/dracut.conf.d/cmdline.conf   # replace the three placeholders
```

## The boot image

The files in `etc/dracut.conf.d` only take effect when the image is rebuilt.
The pacman hook does that on every kernel update. After changing one by hand,
rebuild the image and check that it is signed:

```sh
sudo dracut --force --uefi --kver "$(uname -r)" /boot/efi/EFI/Linux/bootx64.efi
sudo sbctl verify
```

Keep `compress="zstd"` in `flags.conf`. At boot, systemd-stub adds small
archives after the initramfs, and the kernel's lz4 decoder cannot tell where
the lz4 data ends. With lz4 the kernel logs `Initramfs unpacking failed:
Decoding failed` on every boot. The machine still starts, but the added
archives are lost.

## A quiet boot

The boot should show Plymouth and nothing else: no text before it, and none
between the disk password and the login screen. Two things do that.

Three parameters at the end of `cmdline.conf`:

| Parameter | What it does |
| --- | --- |
| `loglevel=3` | Hides kernel error lines. `quiet` alone still prints them |
| `systemd.show_status=error` | systemd prints failures only, never the `[ OK ]` lines |
| `vt.global_cursor_default=0` | Hides the blinking text cursor |

Two parameters to leave out:

- `plymouth.nolog`. Plymouth tells systemd to print its status lines whatever
  `systemd.show_status` says, and normally catches them itself and writes
  them to `/var/log/boot.log`. With `plymouth.nolog` it does not catch them,
  so they land on the screen for a moment before the splash draws.
- `plymouth.use-simpledrm`. It makes Plymouth draw the password prompt on the
  firmware display about three seconds sooner. But the `xe` driver then takes
  the display over, and the screen goes black until `xe` is ready and
  Plymouth draws again.

And `retain-splash.conf`, which makes Plymouth leave its picture on screen
when it quits. Without it the text console shows for about two seconds, until
greetd clears the screen for the login screen.

The hidden messages are all still in `journalctl -b`. If the login screen
cannot start at all, the first console keeps showing the frozen splash;
`Ctrl + Alt + F2` opens a plain console.

## The login screen

The login screen is separate and does not touch the boot image. One command
installs or updates it:

```sh
nocturne greeter preview   # look at it in a window first
nocturne greeter install   # asks for your password
```

`install` copies the screen to `/etc/greetd/nocturne/`, because the greeter's
user cannot read a home folder, puts the script in `/usr/local/bin`, and
points greetd at it. The desktop's cursor goes along: the theme named in
`hypr/lua/env.lua` is copied into `/etc/greetd/nocturne/icons/` if it lives in
your home folder. The config it replaces is kept as
`/etc/greetd/config.toml.before-nocturne`.

greetd reads its config only when it starts, so the first install shows after
you restart the computer; logging out is not enough. (`sudo systemctl restart
greetd` also works, but it ends your session on the spot.) Later updates show
at the next login.

The copies do not follow the repo by themselves. After changing the accent or
the wallpaper, run `nocturne greeter install` again; `nocturne reload` and
`nocturne doctor` say when they are out of date.

**Sessions.** Every login starts Hyprland unless you pick another session in
the bottom-left corner first (click it, or Tab to it and press Enter). GNOME
appears when it is installed, and i3 when it and `xorg-xinit` are; a session
other than Hyprland shows in gold, and the next boot starts at Hyprland
again. `greeter/session.sh` starts each one: GNOME on Wayland, and i3 through
`startx` on the login's console. GDM can stay installed, disabled, as a way
back to GNOME's own login screen.

If the screen cannot start, the script falls back to tuigreet, the text
login, so you can still get in. It starts Hyprland too; F3 there lists the
other sessions. `Ctrl + Alt + F2` opens a plain console as a
last resort. To go back for good:

```sh
sudo cp /etc/greetd/config.toml.before-nocturne /etc/greetd/config.toml
```
